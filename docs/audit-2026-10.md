(AI SDK 6 → 7, `@ai-sdk/react` 3 → 4, Better Auth 1.4.9 → 1.6.21, `@convex-dev/better-auth` 0.10 → 0.12).

## What's done well

**The composer (`src/components/chat/input.tsx`, `input/text-input.tsx`).** This is the best part of the app.
`LayoutGroup` + `layout` on the form and button row, a measured-height animation with a hard cap,
and the pill → card morph driven by content (`\n`, length > 120, files present) all combine into
one motion system instead of separate effects. File chips use `AnimatePresence mode="popLayout"`
and enter/exit cleanly. Image compression runs in a web worker with an optimistic "processing" state.
These are the right instincts, and they'll carry over to the multi-pane layout.

**Streaming persistence engineering (`src/utilities/streamAssistantTurn.ts`).** Even though the roadmap
replaces this, it's well done: throttled writes (250 ms), signature-based dedupe, one write in flight
at a time with coalescing, rAF-batched UI updates, and correct abort handling.

**Convex schema (`convex/schema.ts`).** Forward-looking. Message `parts` mirror AI SDK `UIMessage` parts,
branching is modeled (`parentId`, `branchIndex`, `isActiveBranch`), usage/cost has a home, and indexes match
the queries. `convex/authHelpers.ts` keeps access checks in one place (`requireConversationAccess`, etc.).

**Auth plumbing.** SSR token fetched in the root `beforeLoad`, set on the Convex server client, route guards
via context, three OAuth providers, password reset/verification emails wired. Getting Better Auth + Convex +
TanStack Start SSR working together isn't trivial.

**Home/auth page.** Vertex-displaced plane with layered simplex noise blending five colors, GSAP `SplitText`
masked line reveals, staggered OAuth buttons. Good WebGL practice.

**Small things.** `<think>`-tag reasoning middleware for local models, `t3-env` validation, Biome, and the
intent to use the React Compiler.

## What should improve

### Correctness and security (fix first)

1. **Convex queries try to write.** `getCurrentUserOrNull` (`convex/authHelpers.ts`) calls `ctx.db.insert` /
   `ctx.db.patch`, and it's used inside queries (`users.current`, `messages.list`, `conversations.get`, …).
   Queries are read-only, so this throws for a brand-new user (insert) and whenever a profile field changes
   (patch). Typed as `Ctx = any`, so TypeScript can't catch it. Split into a read-only lookup for queries and
   an upsert used only by `users.getOrCreate`.
2. **Attachment ownership isn't checked.** `messages.sendUserMessage` patches any `attachmentIds` passed in
   without checking they belong to the caller. Once linked to your conversation, `requireAttachmentAccess`
   grants you access. `attachments.create` also accepts any `storageId`.
3. **The client writes assistant output and usage.** `updateAssistantMessage` and `usage.record` are public
   mutations. Any user can rewrite assistant messages in conversations they can access (including other
   members' messages in group chats; the role isn't checked) and can forge token/cost numbers. Persist
   assistant output and usage server-side.
4. **Share links use `Math.random()`** (`convex/sharing.ts`). Use `crypto.getRandomValues`. `getShared` also
   returns the whole conversation document publicly (system prompt, settings, cost, metadata). Return only the
   fields a viewer needs.
5. **Login password field shows the password.** `Field.Control` has no `type="password"` (`src/routes/(auth)/login.tsx`).
   Client schema requires 6 characters; the server requires 8.
6. **Production leaks.** `defaultErrorComponent` renders `err.error.stack` to users. TanStack devtools render in
   production. `/api/chat` logs every full message array with `console.log`.
7. **`/api/chat` has no rate limiting**, and once the model becomes client-selectable it needs an allowlist.
   Better Auth's rate limiter only covers auth endpoints.
8. **Legacy user matching by email** (`findUserByLegacyFields`) can merge identities. Remove it once existing
   users are migrated.
9. **Env var name mismatch to check.** `.env.local` has `DISCORD_SECRET_ID`; `convex/auth.ts` reads
   `DISCORD_CLIENT_SECRET`. Convex reads from its own dashboard env, so this may be fine there. Worth confirming.

### Build and tooling

- **The React Compiler isn't running.** `@vitejs/plugin-react` v6 removed the `babel` option (`vite.config.ts`
  type error). Use `@rolldown/plugin-babel` + `reactCompilerPreset()` per the plugin README.
- **Stay on Better Auth 1.6.x.** `@convex-dev/better-auth@0.12.x` declares `better-auth >=1.6.11 <1.7.0`.
  Better Auth 1.7 is out, but don't bump it until the Convex adapter supports it.
- **Vendored ai-elements drifted** from the AI SDK 7 types (`context.tsx`, `reasoning.tsx`, `tool.tsx`,
  `confirmation.tsx`). Vercel's ai-elements is being deprecated in favor of shadcn/ui's AI Elements patterns, so
  migrate rather than re-pull (roadmap 0.7).
- **Two UI primitive libraries.** Radix comes in through every shadcn component; Base UI is used only by the login
  form, via the deprecated `@base-ui-components/react` rc (renamed to `@base-ui/react`).
- Delete `src/routes/demo/*` (scaffold leftovers with type errors) and `src/hooks/useChatMessages.tsx` (unused;
  hard-codes `qwen/qwen3.5-9b` and passes search params the route doesn't define).
- No tests, no CI, no project `CLAUDE.md`. If agents write most of the code, these are the main way to catch mistakes (see roadmap Phase 0).

### Chat architecture

- **`useChat` isn't used.** `$chatId.tsx` is ~350 lines of hand-managed refs, overlays, and effects that
  re-implement what `useChat` provides (status, stop, regenerate, error, multi-part rendering, tool parts). It
  also ties streaming to Convex, which conflicts with local-first storage and guest users.
- **Streaming only shows text.** The overlay replaces parts with a single text part, so reasoning appears only
  after completion. `ReasoningUI` assumes reasoning is at `parts[1]`.
- **Persistence depends on the tab.** If the tab closes mid-stream, the message is stuck at `streaming` forever.
- **Local models only work on your machine.** `/api/chat` calls `LMSTUDIO_BASE_URL` from the server. Deployed
  to Vercel, the server can't reach anyone's `localhost:1234`. Browser-side calls are needed for "bring your own
  local model" (see roadmap 2.3).

### UI details

- Drag-and-drop skips the type/size validation and compression that the paperclip path does.
- `URL.createObjectURL` previews are never revoked (memory leak on long sessions).
- Image lightbox nests a `<button>` inside a `<button>` (invalid HTML, focus issues).
- Enter submits during IME composition (check `e.nativeEvent.isComposing`).
- On the form, `animation: "border-radius 0.5s ease-in-out"` isn't valid (`animation` needs a keyframes name), and
  `transitionProperty` without a duration does nothing. To tween the radius, put it in `animate={{ borderRadius }}`.
- Icon-only buttons rely on tooltips; add `aria-label`s.
- Landing copy says "Built with Nextjs" (it's TanStack Start) and "found on the of the".
- WebGL scene: cap DPR (`dpr={[1, 1.5]}`), respect `prefers-reduced-motion`, and lazy-load three.js so the login
  route ships less JS. `new THREE.Color("blue")` is created every render for a `color` prop the shader never reads.
